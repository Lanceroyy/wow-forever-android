# WoW Forever Android security audit

Baseline: upstream [v2.3.3 / f13da67](https://github.com/jaredgei/wow-forever-android/tree/f13da6796612146c73bcf5c0758a3a75c01080df). The line links below refer to that baseline so they remain stable. Reviewed the launcher and its game, update, input, Android and build trust boundaries. This was a source and artifact review, not a forensic examination of a victim's APK or a native runtime trace.

| ID | Severity and state | Evidence, conditions and remediation |
|---|---|---|
| WF-01 | Critical; verified, remediated for new launches | [BattleNetSignIn.kt:38–98](https://github.com/jaredgei/wow-forever-android/blob/f13da6796612146c73bcf5c0758a3a75c01080df/app/src/main/java/app/gamenative/ui/screen/wow/BattleNetSignIn.kt#L38-L98) wrote the raw email/password to shared `_forever_/login.txt`; [prepareLaunch:1172–1179](https://github.com/jaredgei/wow-forever-android/blob/f13da6796612146c73bcf5c0758a3a75c01080df/app/src/main/java/app/gamenative/ui/screen/wow/WoWForeverScreen.kt#L1172-L1179) did so before downloading. A second app with all-files access could read it before the log watcher, or after process death. Removed collection and the writer. Startup deletes old preferences without decrypting them, and known handoffs are unlinked on resume and before play. Old files on other roots or offline SD cards need manual cleanup. Unlinking is not secure erasure. |
| WF-02 | High; verified, source remediated | [IMEInputReceiver.kt:81–94 and 124–157](https://github.com/jaredgei/wow-forever-android/blob/f13da6796612146c73bcf5c0758a3a75c01080df/app/src/main/java/app/gamenative/externaldisplay/IMEInputReceiver.kt#L81-L156) logged committed text, individual characters and unmapped characters while forwarding them to the guest. Debug builds plant a debug tree; release may still log the unmapped character warnings. [CrashHandler.kt:69–126](https://github.com/jaredgei/wow-forever-android/blob/f13da6796612146c73bcf5c0758a3a75c01080df/app/src/main/java/app/gamenative/CrashHandler.kt#L69-L126) wrote a copy of logcat to external app files on crash. Removed text and per-key diagnostics and automatic logcat export. Secure-window flags cover launcher and presentation windows; rooted capture, the system IME and guest logging are outside this boundary. |
| WF-03 | Critical; verified, launcher route remediated | [WowClientDownloader.kt:31, 96–127 and 319–344](https://github.com/jaredgei/wow-forever-android/blob/f13da6796612146c73bcf5c0758a3a75c01080df/app/src/main/java/app/gamenative/ui/screen/wow/WowClientDownloader.kt#L319-L344) fetched TACT metadata and CASC content over HTTP. An on-path attacker could replace the expected keys and binaries; [the desktop helper](https://github.com/jaredgei/wow-forever-android/blob/f13da6796612146c73bcf5c0758a3a75c01080df/tools/download_wow_arm64.py#L10-L23) had the same HTTP transport and relied on the local build record. The launcher now uses official TACT v2 over normal TLS and two exact Blizzard CDN hosts, disallows redirects and local metadata fallback, and checks config, install manifest, encoded header, chunks, encoding pages, index checksums and final decoded binary. The obsolete Python downloader was removed. CASC MD5 remains a format checksum, backed by authenticated transport; it is not a signature or independent origin proof. |
| WF-04 | High; verified, bounded in launcher | [WowClientDownloader.kt:199–265 and 487–552](https://github.com/jaredgei/wow-forever-android/blob/f13da6796612146c73bcf5c0758a3a75c01080df/app/src/main/java/app/gamenative/ui/screen/wow/WowClientDownloader.kt#L199-L265) accepted manifest paths, predictable temp files, and deleted the previous file before replacement. A malicious manifest or existing symlink could escape the intended tree; a failed replace could lose the previous file. Reject unsafe paths/symlink components, verify all staged binaries before atomic per-file replacements, publish the executable last and require repair after interrupted publication. Shared storage remains mutable by another privileged app; lexical and symlink checks do not eliminate concurrent races. |
| WF-05 | High; verified, remediated for launcher APK updates | [AppUpdater.kt:45–98, 127–139](https://github.com/jaredgei/wow-forever-android/blob/f13da6796612146c73bcf5c0758a3a75c01080df/app/src/main/java/app/gamenative/utils/AppUpdater.kt#L45-L98) accepted the first APK URL and reused cached content by length. A modified APK or wrong release could reach the installer. Android signature enforcement already limited same-package substitution. Require a fork release and GitHub SHA-256, one allowlisted HTTPS asset redirect, exact installed package and signing certificate set and higher version code; recheck before the normal installer. No signer rotation or unsigned asset exception. |
| WF-06 | Medium; minimized | [AndroidManifest.xml:12–43, 48–84](https://github.com/jaredgei/wow-forever-android/blob/f13da6796612146c73bcf5c0758a3a75c01080df/app/src/main/AndroidManifest.xml#L12-L43) allowed cleartext, declared the mic and exported both activity and launcher alias. Disable cleartext for Android networking, remove RECORD_AUDIO and the Android-to-guest microphone bridge, keep only the launcher alias as an exported activity (including the debug Compose helpers), and limit FileProvider roots to private APK update cache. The AndroidX profile installer receiver remains protected by Android’s DUMP permission. INTERNET and REQUEST_INSTALL_PACKAGES are needed for online game and explicit APK install. API 29 capped READ/WRITE_EXTERNAL_STORAGE and legacy access are kept for shared files on Android 10. MANAGE_EXTERNAL_STORAGE remains for Android 11+ raw paths. |
| WF-07 | High; partial mitigation, native provenance open | [tools/fetch_components.sh:15–32](https://github.com/jaredgei/wow-forever-android/blob/f13da6796612146c73bcf5c0758a3a75c01080df/tools/fetch_components.sh#L15-L32) checked hashes after moving archives into build inputs; [WoWForeverScreen.kt:1310–1347](https://github.com/jaredgei/wow-forever-android/blob/f13da6796612146c73bcf5c0758a3a75c01080df/app/src/main/java/app/gamenative/ui/screen/wow/WoWForeverScreen.kt#L1310-L1347) extracted bundled assets or accepted existing profile/metadata files without verification. Verify inputs before publish, at Gradle prebuild and before fresh extraction. The new bundle extractor stages into private directories, rejects escapes and unsupported entries, and creates bounded internal symlinks after writes. Repository hashes and release digests verify bytes, not that they match source. |
| WF-08 | High; unresolved trust boundary | [Net.kt:33–89](https://github.com/jaredgei/wow-forever-android/blob/f13da6796612146c73bcf5c0758a3a75c01080df/app/src/main/java/app/gamenative/utils/Net.kt#L33-L89), `utils/downloader/` and [TarCompressorUtils.java:167–209](https://github.com/jaredgei/wow-forever-android/blob/f13da6796612146c73bcf5c0758a3a75c01080df/app/src/main/java/com/winlator/core/TarCompressorUtils.java#L167-L209) expose additional GameNative executable content without independent pins. Legacy caches accept nonempty files; generic tar extraction permits paths and links that the new four-asset extractor rejects. Runtime transport is restricted to two HTTPS locations with no automatic redirects, but a compromised publisher/mirror or bad existing cache can still execute code. Review the per-format rootfs links and pin or remove each reachable runtime artifact before trusting credentials. |
| WF-09 | High; unresolved execution and isolation risk | [WoWForeverScreen.kt:1218–1224](https://github.com/jaredgei/wow-forever-android/blob/f13da6796612146c73bcf5c0758a3a75c01080df/app/src/main/java/app/gamenative/ui/screen/wow/WoWForeverScreen.kt#L1218-L1224) maps the shared game folder directly into Wine. Another all-files app can modify an executable, DLL, addon or data after validation. The launcher now removes legacy HTTP CDN advertisements from the active game row using official metadata when needed. Native code can make its own network calls; the Android manifest cannot police all guest sockets. A proven private executable and plugin boundary is required to close this risk. |

## Upstream reports and input paths

- [#33](https://github.com/jaredgei/wow-forever-android/issues/33): both principal vulnerabilities verified in the pinned source. The issue's shadow-root sketch is untested. The guest starts `G:\_forever_\Wow-ARM64.exe` via Wine and uses relative WoW data/config paths. A private G: root with a private executable and selected links to large data is technically plausible under the same Android UID, but the title's executable-directory resolution, DLL lookup, login-file consumption, cancellation, and internal/removable-volume behavior were not demonstrated. The branch creates **no handoff**, private or shared, and does not retain a password to encrypt. Baseline AES-CBC authenticated neither ciphertext nor the separately plaintext email; no credential cipher is carried into this branch.
- [#32](https://github.com/jaredgei/wow-forever-android/issues/32): the account compromise and deliberate keylogger allegation remain unverified. The local keyboard logging in WF-02 is real. Source flow reviewed: Android `MainActivity.dispatchKeyEvent` → `AndroidEvent.KeyEvent` → `XServerScreen`/controller or `Keyboard` → X events → Wine guest. Android external IME `commitText` → character/keycode mapping → same guest keyboard. No outbound transmission of those Android key events was identified in the reviewed Java/Kotlin paths. This cannot exclude behavior in binaries, IMEs, other apps, or the guest.
- [#46](https://github.com/jaredgei/wow-forever-android/issues/46): no precise detection name, signed APK hash, or sample was provided in the report. An antivirus result alone does not establish maliciousness or a false positive. Compare an exact sample's signing certificate and hash and analyze its behavior separately.

Host code includes local process and shell utilities (`com/winlator/core/ProcessHelper.java`), guest executable launch and native library loading, and invokes package installer intents. These capabilities are consistent with an emulator/launcher and increase impact if an input is compromised. No accessibility, notification listener, or device-administrator declaration was found in the app's source manifest. The launcher keeps the existing background guest policy for Authenticator use; device behavior was not measured.

SAF grants URIs rather than persistent general POSIX directory access. The existing picker converts a URI into a raw path; CASC and Wine then open that path and linked files directly, including SD cards. A narrow grant alone cannot satisfy those calls. Future work: keep executable and writable guest state app private, import or stream external CASC content through a scoped bridge, and test device/SD behavior before removing all-files access.

## Component inventory and provenance

See [SECURITY_COMPONENTS.tsv](SECURITY_COMPONENTS.tsv) for individual tracked binary/archive hashes, four fetched bundles, and the runtime catalog. [gradle/libs.versions.toml](gradle/libs.versions.toml) pins the direct Gradle catalog and [settings.gradle.kts](settings.gradle.kts) declares repositories. [SECURITY_GRADLE_DEPENDENCIES.txt](SECURITY_GRADLE_DEPENDENCIES.txt) lists the resolved modern debug runtime coordinates. [THIRD_PARTY_NOTICES](THIRD_PARTY_NOTICES) is the inherited notice list; it is explicitly incomplete. The Gradle 8.12.1 distribution and checked-in wrapper JAR SHA-256 were compared with the official Gradle checksums; the distribution digest is enforced by the wrapper. Independently reproduced binaries and a fully attested transitive dependency set remain out of scope for the available evidence.

Inspected the ELF headers, selected dynamic imports and embedded URL host strings of all 26 tracked ELF inputs. All were AArch64. Network-related imports occur in the DNS shim, PulseAudio and Winlator libraries; several modules use dynamic loading. Imports and strings cannot determine socket destinations or prove that a binary is benign. No native code was executed as part of this inspection.
