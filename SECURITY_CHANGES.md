# Security changes from WoW Forever Android v2.3.3

- Removed the launcher credential dialog, encrypted credential store and plaintext handoff. Existing saved credentials are discarded. Known old handoffs are unlinked before launch and on resume when storage is accessible. **Log in manually** opens the game without a password handoff.
- Removed external IME text and key logging and the automatic crash report that copied logcat. Applied secure flags to launcher and external-display windows. Screenshots, screen sharing and some external displays may be unavailable.
- Switched Blizzard TACT and CASC to official HTTPS locations with certificate/hostname checks, strict range validation and no automatic redirects. Checked the CASC integrity chain and bounded parsers and write paths. Repaired old HTTP CDN advertisements for the active game row when necessary. Staged and verified binaries before publication, and recover interrupted updates before launching.
- Removed microphone permission and the unused guest microphone bridge, and disabled Android cleartext traffic. Kept the launcher alias and private APK provider, narrowed the provider to the APK cache and retained normal Android installer confirmation. Raw shared storage access remains necessary for existing Wine/SD paths.
- Only offer APKs from the configured fork with a valid release-asset SHA-256. Verify the package, current signer set, version name and increasing version code before install; previous download size is never proof of integrity.
- Verify all four bundled component pins during fetch, build and extraction. Stage bundled TAR/ZIP content safely. Add a pinned Gradle distribution checksum, a CI build/test workflow, and a separate optional Android storage probe.
- Retire the duplicate desktop HTTP downloader. USB sync copies existing game data; use the launcher for authenticated executable downloads.

Android 10 now uses the supported display lookup, while ALSA and Vulkan keep their previous numeric settings through named platform constants. Existing GPU profiles, Wine container options, resolution, controller and touch paths, region selection and the guest background policy remain in the code. Manual login, clean installs, SD behavior, Adreno 740 and 8xx, actual input, native streaming and Authenticator resumption still need device validation. The generic GameNative runtime archives and existing shared client files remain material trust boundaries. See the [audit](SECURITY_AUDIT.md) and [test record](SECURITY_TEST_RESULTS.md).
